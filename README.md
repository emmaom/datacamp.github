### How to write a README.md 
A readme is the first file a person would see, and as a data professional it is a crucial skill to communicate a project clearly to others. Consider it to be the instruction manual for our repository.  

A README needs to...
1. be descriptive -> anyone should understand our project
2. List the contents of the repository and how to use it 
3. Clearly explain the project to others

### README fundamentals 

1. Project title
2. Description of the technology used and why
3. A description of the process used to answer the question/ solve a problem and why
4. table of contents

### README extras 

1. Details of **how the project came about**
2. The **motivation** behind the project
3. **Limiations** you encountered during the project
4. **Challenges** you encountered during the project
5. What problem this project intends to **solve**
6. What the projects **intended use** is
7. If we are **sourcing information** from elsewhere it is important to include the **necessary credits**
